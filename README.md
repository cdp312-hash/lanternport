# Daily Trade (working title)

A daily trading game. Everyone gets the same made-up company, with a few months of price history and
a stream of made-up news. Each kind of news moves the price in a learnable way (results keep drifting,
takeover rumours fade, scandals partly recover, fluff does nothing), so reading the news is a skill.
Over 30 days, revealed one at a time, you choose how
much of £10,000 to have invested (cash, 25%, 50%, 75% or all in). Trades fill at the next day's
open with a 0.1% fee. At the end you see your return against buy-and-hold, perfect hindsight and
1,000 random traders, then a recap of what each headline did and the lesson behind it.

Because everything is made up there's no data to license and nothing to look up. A "real history"
mode (real stocks, with the company and year shown) is also supported for later, once there's a
licensed data source: `backtest puzzles --mode history` writes those puzzles outside the game folder.

"Tradle" is already the name of another daily game, so the name is still to be decided. It is set
once, as `TITLE` in [src/App.tsx](src/App.tsx) (plus the `<title>` in [index.html](index.html)).

## Run it

```
./install.ps1        # first time only: npm install, with node_modules kept outside OneDrive
npm run dev          # http://localhost:5174 while editing
npm run build        # type-check and build the static site into dist/
npm run preview      # serve dist/ at http://localhost:4174
npm test             # game logic tests
```

Useful URLs: `?n=12` plays puzzle 12 as practice; `?autoplay` finishes a practice round with random
choices (for checking the results screen); `?skiphelp` hides the first-visit instructions.

## Puzzles

Puzzles are generated from the backtester's data code and stored as small JSON files in
`public/puzzles/` (one per day plus `index.json`, which records the date of puzzle #1):

The site is built around the world of **Lanternport**: a daily newspaper (*The Lanternport Ledger*),
a Markets page and a page per company. The trading game uses rounds from the Ledger's archive (years
of simulated backstory that are never published, so outcomes can't be looked up).

Everything is generated by the world engine in the (private) parent project:

```
cd ..
backtest world --through 2026-10-16     # editions up to that date + 365 archive puzzles
```

This writes `public/world/` (index, one file per edition, one per company) and `public/puzzles/`.
Only editions up to `--through` are written; later days are simulated but kept back, so republish
each day to put out the next morning's paper. World content (companies, bosses, storylines and their
headlines) lives in plain YAML in `backtester/world/data/` and can be edited freely.

Generating also runs a balance check: a bot that reads every headline correctly should usually beat
random traders and buy and hold, but not always (currently about 87% and 69% for world rounds).

The game picks the puzzle for the player's local date and cycles once it runs out. Prices are
rescaled so the last price before day 1 is 100. The recap is base64-encoded in the files, which deters
casual peeking but nothing more.

## Hosting on GitHub Pages

This folder is its own git repository. [.github/workflows/deploy.yml](.github/workflows/deploy.yml)
builds, tests and publishes the game on every push to `main`.

1. Create a **public** repository on GitHub (free Pages hosting needs a public repo), without a README.
2. Push this folder to it: `git remote add origin <repo URL>` then `git push -u origin main`.
   Git Credential Manager opens a browser window to sign in the first time.
3. In the repository: **Settings > Pages > Source: GitHub Actions**. Then re-run the workflow from the
   **Actions** tab (or push again). The game appears at `https://<username>.github.io/<repo>/`.
4. Optional custom domain: **Settings > Pages > Custom domain**, plus a DNS record at your registrar.

`dist/` is a plain static site with relative paths, so Cloudflare Pages or Netlify work too.

## Ads

Ads come from Google AdSense and are off until configured. AdSense only approves live sites, so publish first.

1. Sign up at adsense.google.com with the site's address and wait for approval.
2. In AdSense, create two display ad units (one for under the results, one for the footer) and switch on
   **Privacy & messaging > European regulations message** (the consent banner UK and EEA visitors need).
3. In the GitHub repository, add Actions **variables**: `ADSENSE_CLIENT` (e.g. `ca-pub-1234…`),
   `AD_SLOT_RESULT` and `AD_SLOT_FOOTER`. The next deploy shows ads and writes `ads.txt`.
4. Fill in the bracketed parts of [public/privacy.html](public/privacy.html) before going live.

Ads are placed under the results and in the footer, away from the trading buttons; AdSense forbids
placements that invite accidental clicks.

The published puzzles are fictional. Real-history puzzles use Yahoo Finance data, which is for
personal use only, so don't put those in `public/` without a licensed data source.
